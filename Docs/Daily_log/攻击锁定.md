## 问题现象

- 锁定系统的**逻辑完全正常**：Console 里反复出现 `[LockOn] 锁定 Slime (1)` 和 `[LockOn] 解除锁定`。
- 但**画面上永远看不到红框**，无论锁定了多少次。

---

## 根本原因

**脚本挂在了它自己要 `SetActive(false)` 的那个 GameObject 上。**

看你的 `LockOnIndicator.cs` 代码：

```csharp
private void Awake()
{
    if (indicatorRoot == null) indicatorRoot = GetComponent<RectTransform>();
    if (indicatorRoot != null) indicatorRoot.gameObject.SetActive(false);  // ← 这里
    EventBus.Subscribe<LockOnChangedEvent>(OnLockOnChanged);
}
```

而你 Inspector 里的 `Indicator Root` 指向的是**自己**（`LockOnIndicator` 这个 GameObject）。

于是发生了这个死循环：

1. `Awake` 里 `LockOnIndicator` 把自己 `SetActive(false)`。
2. **Unity 的规则：GameObject 被 `SetActive(false)` 后，它上面所有 MonoBehaviour 的 `Update` / `LateUpdate` 全部停止执行。**
3. `LateUpdate` 里本来应该做的 `indicatorRoot.gameObject.SetActive(true)` **永远不会被执行到**。
4. 结果：锁定的逻辑在跑，红框永远显示不出来。

这是 Unity 的经典陷阱——**一个对象不能既负责"禁用自己"，又负责"启用自己"**。

---

## 解决方案

**拆成"控制者"和"被控制者"两个层级**：

```
LockOnIndicator（脚本挂这里，永远 active，负责控制）
└── Box（被 SetActive 控制，红框元素都挂在这下面）
    ├── Top
    ├── Bottom
    ├── Left
    ├── Right
    └── Pointer
```

**操作步骤**：

1. 选中 `LockOnIndicator`，右键 → `Create Empty`，命名 `Box`。
2. 把 `Top`、`Bottom`、`Left`、`Right`、`Pointer` **全部拖到 `Box` 下**。
3. 选中 `LockOnIndicator`（父节点），在 `LockOnIndicator` 组件里把 `Indicator Root` 字段改成指向 `Box`（不是自己）。

**原理**：
- 脚本所在的 `LockOnIndicator` 永远 active，`Update` / `LateUpdate` 永远在执行。
- 被禁用/启用的是子物体 `Box`，它被禁用时脚本还在跑。
- 事件到来时，脚本能立刻 `Box.SetActive(true)`，红框就显示出来了。

---

## 你在这次问题里学到的通用经验

1. **`SetActive(false)` 会停掉该 GameObject 上的所有 MonoBehaviour**，包括 `Update`、`LateUpdate`、`OnEnable`（后续也不会）、协程。
2. **控制者 ≠ 被控制者**。一个脚本要控制某个 GameObject 的显隐，就不应该挂在那个 GameObject 上，除非它永远不隐藏自己。
3. **这不是你代码逻辑的错，而是 GameObject 层级设计的错**。Unity 的组件模型没有"自禁用还能自恢复"这种机制，必须靠外部控制者。
4. **同类场景还有**：面板管理器控制面板的显隐、UI 管理器控制 UI 的激活状态、特效控制器控制特效的开和关。**只要是"显示-隐藏"关系，都要遵守这个层级原则**。

## 面试时怎么讲

> "我做锁定 UI 时踩过一个坑：一开始把指示器脚本挂在要被隐藏的 GameObject 上，结果它一 `SetActive(false)` 自己就停了，`LateUpdate` 不再执行，再也无法重新显示。后来我把控制逻辑和显示元素分层——父节点挂脚本、子节点挂 UI 元素，父节点永远 active，只切换子节点的显隐。这是 Unity 里做 UI/特效显隐的标准结构，本质是'控制者与被控制者必须解耦'。"

这段回答展示了你**理解 Unity 生命周期**，也展示了你**有层级设计意识**，是一个很实在的工程经验。
